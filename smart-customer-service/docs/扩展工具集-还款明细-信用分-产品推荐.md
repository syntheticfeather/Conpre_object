## 1. 改造总览

本次为智能客服新增三项能力，遵循 Workflow 分层架构：

- **还款明细查询** / **信用分查询** → 结构化数据查询，归 Java Workflow 层
- **产品推荐** → 需 LLM 组织个性化回复，归 Python Agent 工具

```
重构前:
  用户消息 → Router 分类 → WORKFLOW(QueryStatus/Calculate/ListProducts/ApplyLoan)
                         → AGENT(search_web / search_knowledge)

重构后:
  用户消息 → Router 分类 → WORKFLOW(QueryStatus/Calculate/ListProducts/ApplyLoan
                                     + RepaymentDetail + CreditScore)    ← 新增 2 个 Handler
                         → AGENT(search_web / search_knowledge
                                  + recommend_products)                  ← 新增 1 个工具
```

信用分查询按需求复用 `GET /api/users/me`，在 `UserSelfResponse` 中新增 `creditScore` 字段，不新建接口。

### Java 侧

| 文件路径 | 类型 | 作用说明 |
|---------|------|---------|

## 6. 注意事项与后续

1. **eval_cases 变更**：原 tool_013~020（8 条）期望 `calculate_repayment`/`query_application_status`，这两个能力已上移 Workflow 不再是 Agent 工具，已删除；新增 3 条 `recommend_products` 用例（tool_013~015）。route 组新增 6 条（route_061~066）覆盖 QUERY_REPAYMENT/QUERY_CREDIT。
2. **MongoDB 提示词**：`DEFAULT_GENERAL_RULES` 已更新内置默认值，但 MongoDB 中 `general` category 的 `business_rules` 如有旧版 `calculate_repayment`/`query_application_status` 引用，需通过管理后台更新（TTL 60s 自动生效）。
3. **产品推荐为规则打分版本**：当前 `recommendProducts` 使用信用分+利率+额度的硬规则打分，后续可演进为基于内容推荐（用户画像向量+产品特征向量余弦相似度）。
4. **Java 服务需重启**：新增 Handler 和接口需重启 Java 服务生效；ChatRouterService 会自动扫描 `@Component` Handler 注册。
5. **`JAVA_URL` 环境变量**：`recommend_tools.py` 依赖此变量连接 Java 后端，确保 Python 服务环境中已配置。
