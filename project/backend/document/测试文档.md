# 测试文档

## 分布式锁（AOP + Redisson）有效性测试

### 结论

在单节点本地环境下，可以通过并发调用同一业务方法来模拟“重复触发”场景，从而验证 AOP 切面是否生效、以及“抢锁失败/等待抢锁/失败抛错”三类策略是否符合预期。本次测试已通过。

说明：由于当前未部署 Redis/未保证本机 Redis 常驻，测试采用 Mock RedissonClient + 线程并发的方式验证切面逻辑与互斥语义；该测试覆盖“方法级互斥是否生效”，但不覆盖“跨进程/跨节点/Redis 网络异常”等真实分布式环境问题。

### 测试范围

- 验证 `@RedisLocked` 的 AOP 拦截是否生效（切面是否执行 tryLock/unlock）
- 验证并发情况下同一 key 的互斥行为
- 验证锁获取失败时的两种策略：返回 null / 抛 BusinessException
- 验证配置 waitTime 时的“等待抢锁后成功”行为

### 测试用例

#### 用例 1：并发重复触发，抢锁失败返回 null

- 场景：线程 A 先进入并持有锁，线程 B 立即并发调用同一 key 的方法
- 预期：B 无法获取锁，直接返回 null；A 正常执行并返回
- 覆盖点：`waitTime=0` + `returnNullOnFail=true`

#### 用例 2：并发重复触发，设置 waitTime 后等待成功

- 场景：线程 A 持有锁一小段时间；线程 B 并发调用同一 key 的方法并等待
- 预期：B 在 waitTime 内等到锁释放后成功执行
- 覆盖点：`waitTime>0`

#### 用例 3：并发重复触发，抢锁失败抛业务异常

- 场景：线程 A 先持有锁；线程 B 并发调用同一 key 的方法
- 预期：B 抛 `BusinessException(failCode, failMessage)`
- 覆盖点：`returnNullOnFail=false` + failCode/failMessage 自定义

### 结果

- 用例 1/2/3 全部通过

### 局限与后续建议

- 若需要验证“真实 Redis 分布式锁”在本机是否有效，可在本机启动 Redis 后，新增/开启基于真实 RedissonClient 的集成测试（需要确保测试环境具备 Redis 依赖，且测试用例可重复执行）。
