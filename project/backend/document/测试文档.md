# 测试文档

## 分布式锁（AOP + Redisson）有效性测试

### 结论

在单节点本地环境下，可以通过并发调用同一业务方法来模拟"重复触发"场景，从而验证 AOP 切面是否生效、以及"抢锁失败/等待抢锁/失败抛错"三类策略是否符合预期。本次测试已通过。

说明：由于当前未部署 Redis/未保证本机 Redis 常驻，测试采用 Mock RedissonClient + 线程并发的方式验证切面逻辑与互斥语义；该测试覆盖"方法级互斥是否生效"，但不覆盖"跨进程/跨节点/Redis 网络异常"等真实分布式环境问题。

### 测试范围

- 验证 `@RedisLocked` 的 AOP 拦截是否生效（切面是否执行 tryLock/unlock）
- 验证并发情况下同一 key 的互斥行为
- 验证锁获取失败时的两种策略：返回 null / 抛 BusinessException
- 验证配置 waitTime 时的"等待抢锁后成功"行为

### 测试用例

#### 用例 1：并发重复触发，抢锁失败返回 null

- 场景：线程 A 先进入并持有锁，线程 B 立即并发调用同一 key 的方法
- 预期：B 无法获取锁，直接返回 null；A 正常执行并返回
- 覆盖点：`waitTime=0` + `returnNullOnFail=true`

#### 用例 2：并发重复触发，设置 waitTime 后等待成功

- 场景：线程 A 持有锁一小段时间；线程 B 并发调用同一 key 的方法并等待
- 预期：B 在 waitTime 内等到锁释放后成功执行
- 覆盖点：`waitTime>0`

#### 用例 3：并发重复触发，抢锁失败抛业务异常

- 场景：线程 A 先持有锁；线程 B 并发调用同一 key 的方法
- 预期：B 抛 `BusinessException(failCode, failMessage)`
- 覆盖点：`returnNullOnFail=false` + failCode/failMessage 自定义

### 结果

- 用例 1/2/3 全部通过

### 局限与后续建议

- 若需要验证"真实 Redis 分布式锁"在本机是否有效，可在本机启动 Redis 后，新增/开启基于真实 RedissonClient 的集成测试（需要确保测试环境具备 Redis 依赖，且测试用例可重复执行）。

## 消息队列（RabbitMQ + Outbox）单元测试

### 结论

在不依赖真实 RabbitMQ/数据库的前提下，使用 Mockito 对 Mapper/RabbitTemplate/Channel 进行隔离，通过"构造 AMQP Message + 注入 mock 依赖"的方式验证消息消费、幂等、落库/写 outbox、DLQ 处理、以及 Confirm/Return 回调对 outbox 状态更新的逻辑。本次测试已通过（`mvn test`）。

### 测试范围

- Outbox 轮询投递：从 outbox 取消息、抢占 SENDING、构造带 messageId header 的 AMQP Message 并投递
- 生产侧回调：ConfirmCallback/ReturnsCallback 对 outbox 的 SENT/FAILED 状态标记
- 消费侧：
  - payment.requested.queue：模拟三方支付 -> 写 outbox(payment.success) -> Ack
  - payment.success.queue：记录支付流水、更新订单、写 outbox(order.repaid) -> Ack
  - order.repaid.queue：写站内通知 + SSE publish -> Ack
  - loan.application.queue / notification.queue：幂等、失败重试上限后入 DLQ、Ack/Nack 行为

### 测试用例

| 测试类 | 测试场景 | 验证点 |
| :--- | :--- | :--- |
| `OutboxMessagePollerTest` | Outbox 轮询投递 | PENDING -> SENDING 成功后调用 RabbitUtil.sendToApp，消息 header 包含 messageId；抢占失败时跳过投递；投递异常时标记为 FAILED |
| `RabbitTemplateConfigTest` | 生产侧回调 | ConfirmCallback ack -> markAsSent；ConfirmCallback nack -> markAsFailed；ReturnsCallback（NO_ROUTE）-> markAsFailed |
| `PaymentRequestedConsumerTest` | 支付请求消费 | 正常消费：调用 PayService 并写 outbox(payment.success)；缺少 messageId：转入 DLQ 并 Ack；幂等命中：直接 Ack |
| `PaymentSuccessConsumerTest` | 支付成功消费 | 正常消费：写支付流水、更新订单、发送还款通知；支付流水重复：直接 Ack 并停止后续更新；缺少 messageId：转入 DLQ 并 Ack |
| `LoanApplicationConsumerTest` | 贷款申请消费 | 正常消费：调用审批服务并写幂等记录；缺少 messageId：Nack；达到最大重试次数：转入 DLQ 并 Ack |
| `NotificationConsumerTest` | 通知消费 | 正常消费：写通知并 SSE publish；缺少 messageId：Nack |
| `NotificationOutboxPublisherTest` | 通知发布 | 调用 enqueueNotification/enqueueAdminNotification 后写入 outbox |
