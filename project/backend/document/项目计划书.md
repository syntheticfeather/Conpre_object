# 综设2项目计划书

## 16周项目计划

### 第1-2周：项目架构优化与基础功能完善

**任务目标**：

- 优化项目架构，确保代码质量
- 完善基础功能，修复现有bug
- 提高系统稳定性和安全性

**具体任务**：

1. 代码审查与重构
   - 全面审查现有代码，识别代码潜在问题，包括重复代码、过长方法、复杂条件判断等
   - 优化Controller层代码，统一返回格式和异常处理，使用统一的ApiResponse封装响应结果
   - 重构Service层，提高代码复用性和可维护性，提取通用业务逻辑到公共服务
   - 优化Mapper层SQL语句，避免N+1查询问题，使用批量查询和关联查询优化
   - 完善异常处理机制，统一异常处理流程，使用自定义异常类和全局异常处理器

2. 安全性增强
   - 加强所有接口的输入参数验证，确保数据合法性
   - 完善密码加密机制，设置合理的加密强度
   - 实现JWT token刷新机制，提高安全性，设置token过期时间和刷新策略
   - 添加接口访问频率限制，防止暴力攻击，使用Redis实现限流
   - 配置CORS策略，限制跨域访问，设置允许的域名和请求方法

3. 文档完善
   - 更新所有接口文档，补充请求参数和响应示例
   - 编写系统架构文档，描述各模块之间的关系，使用架构图可视化展示
   - 更新API接口文档

### 第3-4周：Web爬虫技术集成

**任务目标**：

- 集成Python爬虫技术
- 实现数据爬取和处理功能
- 为风控系统提供外部数据源

**具体任务**：

1. 爬虫系统设计
   - 明确数据源与字段，优先选择合法公开数据源，定义核心风控字段
   - 制定爬虫策略，技术栈：Python + requests + BeautifulSoup/XPath，存储：写入MySQL
   - 基础反爬策略,固定User-Agent + 随机延时（1~3秒）+ 遵守robots.txt

2. 爬虫技术实现
   - 实现2~3个核心数据源的爬虫脚本（例如：工商信息 + 失信被执行人）
   - 使用 requests 获取页面，BeautifulSoup 解析结构化数据
   - 数据清洗：统一日期格式、去除HTML标签、空值处理
   - 去重机制：基于 (user_id, data_source, crawl_date) 建立唯一索引
   - 异常处理：网络超时重试（最多3次）、记录失败日志（文件或DB）
   - 日志记录：记录爬取时间、成功/失败数量、关键错误信息

3. 与后端系统集成
   - 设计RESTful API接口
   - 实现数据同步机制，定时同步爬取的数据到后端数据库，使用批量插入优化
   - 实现爬虫任务队列，使用RabbitMQ管理任务，确保任务可靠执行,实现爬虫结果通知机制，及时通知后端数据更新，使用WebSocket或消息队列
   - 实现爬虫性能监控，统计爬取成功率和速度，生成性能报告

### 第5-6周：数据存储与处理优化

**任务目标**：

- 优化数据存储结构
- 提高数据处理效率
- 实现数据缓存策略

**具体任务**：

1. Redis缓存优化
   - 设计合理的缓存策略,包括用户基本信息、贷款产品信息的缓存。
   - 实现热点数据缓存，如热门贷款产品的快速访问。
   - 设置合理的过期时间，根据业务需求调整。

2. 数据库优化
   - 分析现有数据库表结构，优化不合理的设计，如冗余字段、不合适的数据类型
   - 创建必要的索引以加速查询，特别是对于频繁使用的外键和查询条件。
   - 用EXPLAIN分析并优化关键查询语句。

3. 数据处理流程优化
   - 简化数据处理逻辑，利用缓存减少重复计算。
   - 实现批量处理机制，如批量插入更新操作，提高效率。
   - 基本实现文件上传下载流程优化，支持大文件传输的基本功能。
   - 实现数据归档机制，定期归档历史数据，减少主表数据量

### 第7-8周：风控评分卡设计与实现

**任务目标**：

- 设计评分卡模型
- 实现评分卡算法
- 集成评分卡到贷款审批流程

**具体任务**：

1. 评分卡模型设计
   - 研究评分卡理论基础，了解评分卡建模流程，包括数据准备、特征工程、模型训练等
   - 确定评分维度，包括基本信息、征信信息、收入信息等，每个维度包含具体的特征项
   - 设计评分规则，制定各维度的评分标准，如年龄、收入水平、信用记录等的评分规则
   - 确定权重分配，根据业务需求调整各维度权重，使用层次分析法或专家打分法
   - 制定评分标准，设定通过分数线和拒绝分数线，根据业务风险承受能力确定

2. 特征工程
   - 提取并清洗核心特征，如征信信息、收入信息等。
   - 处理缺失值和异常值，采用简单的填充或删除方法。
   - 进行特征标准化，使数据适合模型训练。

3. 评分卡实现
   - 使用逻辑回归初步构建评分模型，并进行效果评估。
   - 实现评分计算逻辑，将其集成到贷款审批流程中。
   - 开发简易测试工具，验证评分准确性。

### 第9-10周：AI审批系统开发

**任务目标**：

- 开发AI自动审批系统
- 实现智能风险评估
- 提高审批效率

**具体任务**：

1. AI审批系统设计
   - 设计AI审批流程，确定自动审批的触发条件，如评分达到一定阈值
   - 确定审批规则，制定自动通过和自动拒绝的标准，明确决策边界
   - 制定审批策略，包括评分阈值、风险等级划分，根据业务风险偏好调整
   - 设计AI审批与人工审批的切换机制，明确何时需要人工介入
   - 设计审批结果追溯机制，记录审批决策依据，包括评分结果、特征贡献等
   - 设计审批规则管理，支持动态调整审批规则，适应业务变化
   - 制定AI审批的监控和预警机制，及时发现模型异常和性能下降

2. 风险评估模型
   - 实现基于评分卡的风险评估算法，结合评分结果和其他风险指标
   - 集成外部数据源，包括征信数据、工商数据等，丰富风险评估维度
   - 开发风险评估接口，供其他模块调用，返回风险等级和详细评估结果
   - 实现风险等级划分，将风险分为低、中、高三个等级，制定不同的处理策略
   - 实现风险预警机制，对高风险申请进行预警，及时通知审批人员
   - 实现风险评估结果缓存，提高评估效率，避免重复计算
   - 开发风险评估模型训练功能，支持模型迭代优化，使用新数据重新训练
   - 实现模型A/B测试，对比不同模型效果，选择最优模型

3. 与人工审批集成
   - 设计AI与人工审批的协作机制，明确各自的职责，如AI处理常规案件，人工处理复杂案件
   - 实现审批结果的处理，包括自动通过、自动拒绝、人工审核，根据风险等级自动分流
   - 开发审批管理界面，支持审批人员查看和处理申请，提供详细的申请信息和风险评估结果
   - 实现审批任务分配，将待审批任务分配给审批人员，根据工作量和专长自动分配
   - 开发审批历史查询，支持查看申请的审批历史，包括审批时间、审批人、审批意见等
   - 实现审批效率统计，统计AI审批和人工审批的效率，分析审批时间和准确率
   - 开发审批质量监控，监控审批决策的准确性，分析审批错误和改进空间

### 第11-12周：系统集成与测试

**任务目标**：

- 集成所有功能模块
- 进行全面测试
- 修复测试中发现的问题

**具体任务**：

1. 模块集成
   - 集成爬虫模块，确保爬虫数据能正常同步到后端，验证数据一致性和完整性
   - 集成评分卡模块，确保评分功能正常工作，验证评分结果的准确性
   - 集成AI审批模块，确保自动审批流程正常，验证审批决策的合理性
   - 集成人工审批模块，确保人工审核流程正常，验证任务分配和处理功能
   - 集成缓存模块，确保Redis缓存正常工作，验证缓存命中率和性能
   - 集成消息队列，确保RabbitMQ消息正常传递，验证消息可靠性和处理速度
   - 进行端到端测试，验证整个业务流程，从贷款申请到审批完成的完整流程
   - 进行接口联调，确保各模块接口正常调用，验证接口参数和返回值

2. 系统测试
   - 编写单元测试，覆盖核心业务逻辑，使用JUnit等测试框架
   - 编写集成测试，测试模块间的交互，验证模块协作的正确性
   - 进行性能测试，测试系统在高并发下的表现，使用JMeter等压测工具
   - 进行压力测试，测试系统的极限承载能力，确定系统瓶颈
   - 进行安全测试，测试系统的安全漏洞，使用OWASP ZAP等安全测试工具
   - 进行兼容性测试，测试在不同环境下的兼容性，如不同浏览器、不同设备
   - 进行回归测试，确保修复bug不影响其他功能，验证系统稳定性
   - 进行用户验收测试，确保系统满足用户需求，收集用户反馈

3. 问题修复
   - 记录测试中发现的所有问题，建立问题跟踪表，包括问题描述、严重程度、复现步骤
   - 分析问题原因，制定修复方案，评估修复影响和风险
   - 修复测试中发现的bug，确保问题得到解决，编写修复代码和测试用例
   - 优化系统性能，提高系统响应速度，如优化数据库查询、调整缓存策略
   - 提高系统稳定性，减少系统崩溃和异常，增强错误处理和容错能力
   - 进行代码审查，确保修复代码的质量，符合代码规范和最佳实践
   - 重新测试修复后的功能，确保问题彻底解决，验证修复效果

### 第13-14周：部署与监控系统

**任务目标**：

- 部署系统到生产环境
- 实现系统监控
- 制定运维策略

**具体任务**：

1. 部署准备
   - 配置生产环境，包括服务器、数据库、缓存等，确保环境符合系统要求
   - 准备部署脚本，实现自动化部署，使用Shell脚本或CI/CD工具
   - 制定部署计划，包括部署时间、回滚方案，确保部署过程可控
   - 准备生产环境配置文件，修改数据库连接等配置，确保配置正确
   - 准备数据库初始化脚本，创建生产环境数据库，导入初始数据
   - 进行部署演练，确保部署流程顺畅，识别和解决潜在问题
   - 制定数据备份方案，确保数据安全，定期备份数据库和重要文件
   - 制定应急预案，处理部署过程中可能出现的问题，如服务启动失败、数据库连接异常等

2. 系统部署
   - 部署后端服务，使用Docker容器化部署，确保环境一致性
   - 部署爬虫服务，配置定时任务，确保爬虫正常运行
   - 配置数据库，导入初始数据，设置数据库参数和优化配置
   - 配置Redis缓存，设置缓存策略，调整内存限制和过期时间
   - 配置RabbitMQ消息队列，创建交换机和队列，设置消息持久化
   - 配置Nginx反向代理，实现负载均衡，提高系统可用性
   - 配置SSL证书，启用HTTPS，确保数据传输安全
   - 进行部署验证，确保所有服务正常运行，测试核心功能

3. 监控系统
   - 实现系统监控，监控服务器CPU、内存、磁盘等资源，设置资源使用阈值
   - 实现应用监控，监控应用运行状态和性能指标，如响应时间、错误率等
   - 实现数据库监控，监控数据库连接数、查询性能等，识别慢查询和异常
   - 实现缓存监控，监控Redis命中率和内存使用情况，优化缓存策略
   - 实现日志监控，收集和分析应用日志，使用ELK等日志分析工具
   - 配置告警机制，在异常情况发生时及时通知，使用邮件、短信等通知方式
   - 开发监控dashboard，可视化展示监控数据，提供实时和历史数据视图
   - 实现性能分析，定期分析系统性能瓶颈，制定优化方案
