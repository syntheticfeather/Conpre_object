# 个人贷款业务完善

> 目标：围绕 personal-loan 项目完成四项业务增强 + 种子数据补全
> 1. 提前还款接口拓展：用户可选择提前还多少期（原仅支持一次性结清剩余全部）
> 2. loanProduct 增加产品类型字段（个人消费 / 农业生产 / 企业经营）
> 3. 新增订单统计接口：统计用户所有订单的待还总额、待还本金、待还利息
> 4. 订单详情增加金额字段：应还总额、待还总额、待还本金、待还利息

## 一、提前还款接口拓展（支持选择期数）

### 1.1 问题

原 `POST /api/orders/{orderId}/early-repay` 只支持一次性结清剩余全部期数，用户无法选择只提前还 N 期。

### 1.2 方案

接口新增可选参数 `periods`，沿支付事件链向下传递，消费端按期数结清对应还款计划：

```
POST /api/orders/{orderId}/early-repay?periods=N   (N 可选，不传则结清全部)
   │
   ▼
OrderController.earlyRepayOrder(orderId, periods)
   │  校验 periods ∈ [1, remaining]
   │  计算 totalEarlyAmount = Σ(选中未还期数的 principal + interest)
   ▼
PaymentRequestedEvent(orderId, amount, requestTime, periods)  ← 新增 periods 字段
   │  写入 outbox_message
   ▼
PaymentSuccessConsumer 消费成功事件
   │  periods != null → 按 periods 结清；null → 结清全部剩余
   ▼
更新 repayment_schedule 状态 + orders.current_term
```

### 1.3 关键改动

| 文件 | 改动 |
| --- | --- |
| `OrderController.java` | `earlyRepayOrder` 增加 `@RequestParam(required = false) Integer periods` |
| `OrderServiceImpl.java` | `earlyRepay(orderId, periods)`：校验期数范围、按期数累加金额、投递事件 |
| `dto/PaymentRequestedEvent.java` | 新增 `Integer periods` 字段（null = 结清全部） |
| `dto/PaymentSuccessEvent.java` | 新增 `Integer periods` 字段，向消费端透传 |
| `mq/PaymentSuccessConsumer.java` | 按 periods 结清对应期数的还款计划；null 时结清全部剩余 |

### 1.4 校验规则

- `periods == null`：结清剩余全部期数（向后兼容）
- `periods < 1`：抛 `BusinessException(400, "提前还款期数必须大于0")`
- `periods > remaining`：抛 `BusinessException(400, "提前还款期数不能超过剩余期数(N)")`
- 订单已结清（`currentTerm >= term`）：抛 `BusinessException("订单已结清，无需提前还款")`

## 三、订单统计接口

### 3.1 接口

```
GET /api/orders/statistics
Header: Authorization: Bearer <token>

→ {
    "code": 200,
    "data": {
      "totalOutstandingAmount": 12500.00,
      "totalOutstandingPrincipal": 10000.00,
      "totalOutstandingInterest": 2500.00
    },
    "message": "操作成功"
  }
```

### 3.2 实现要点

统计 SQL 关联 `repayment_schedule` 与 `orders`，按 `user_id` 聚合、排除已还期数：

```sql
SELECT
  COALESCE(SUM(rs.principal + rs.interest), 0) AS totalOutstandingAmount,
  COALESCE(SUM(rs.principal), 0)             AS totalOutstandingPrincipal,
  COALESCE(SUM(rs.interest), 0)              AS totalOutstandingInterest
FROM repayment_schedule rs
JOIN orders o ON rs.order_id = o.id
WHERE o.user_id = #{userId} AND rs.status != '已还'
```

### 3.3 关键改动

| 文件 | 改动 |
| --- | --- |
| `OrderController.java` | 新增 `GET /api/orders/statistics` |
| `OrderServiceImpl.java` | 新增 `getUserOrderStatistics(userId)`：调 mapper 聚合，null 兜底零值 |
| `mapper/RepaymentScheduleMapper.java` | 新增 `sumOutstandingByUserId(userId)` |
| `dto/OrderStatisticsResponse.java` | 新建 DTO：`totalOutstandingAmount / Principal / Interest` |

## 四、订单详情增加金额字段

### 4.1 接口

`GET /api/orders/{orderId}` 响应在原有 `productName` + `order` 基础上新增 4 个金额字段：

| 字段 | 含义 | 计算方式 |
| --- | --- | --- |
| `totalAmountDue` | 应还总额 | Σ 所有期数 `total_amount` |
| `outstandingAmount` | 待还总额 | Σ 未还期数 `principal + interest` |
| `outstandingPrincipal` | 待还本金 | Σ 未还期数 `principal` |
| `outstandingInterest` | 待还利息 | Σ 未还期数 `interest` |

### 4.2 关键改动

| 文件 | 改动 |
| --- | --- |
| `dto/UserGetOrderResponse.java` | 新增 4 个 `BigDecimal` 字段 |
| `OrderServiceImpl.java` | `userGetOrder(userId, orderId)`：查还款计划后遍历累加 4 项金额，填充到响应 |

## 七、验证要点

- **提前还款**：传 `periods=3` 时，`PaymentRequestedEvent.periods=3`；不传时 `periods=null` 结清全部；`periods` 超剩余期数返回 400。
- **产品类型**：执行 V1.5 迁移后 `SELECT product_type FROM loan_products` 列存在；`GET /api/loan-products/user` 响应含 `productType` 字段。
- **订单统计**：无订单或全部已还时返回三项零值；有未还时金额 = 各未还期数之和。
- **订单详情**：`GET /api/orders/{orderId}` 响应含 4 个金额字段，`outstandingAmount = outstandingPrincipal + outstandingInterest`。
- **种子数据**：执行 V1.0 后 `loan_products` 共 9 行（个人消费 2、农业生产 2、企业经营 5），上架产品 8 款（季节备货贷已下架）。
