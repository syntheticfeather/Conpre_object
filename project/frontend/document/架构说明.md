# 前端架构说明

## 一、项目概述

本项目是一个借贷APP管理员控制系统，采用 Vue 3 + Pinia + Vue Router 技术栈，使用 Element Plus 和 Ant Design Vue 作为 UI 组件库。集成了 ECharts、Three.js 数据可视化，SSE 实时通知推送，以及基于 SSE 的 AI 智能对话功能。

## 三、各模块职责划分

### 3.1 API 模块 (`src/api/`)

负责与后端 API 的通信，统一管理所有接口请求。基于 Axios 封装，自动注入 Token、处理刷新令牌逻辑。

| 文件 | 职责 |
|------|------|
| `auth.js` | 密码/短信登录、注册、Token 刷新、认证信息查询 |
| `user.js` | 用户统计、详情查询、黑名单管理、信誉分搜索 |
| `loan.js` | 贷款产品 CRUD、状态切换、批量删除、选项管理 |
| `application.js` | 申请审核（含延期申请）：待办/已办列表、详情、审核提交 |
| `loanApplication.js` | 贷款申请查询（按用户、按ID、我的申请） |
| `notification.js` | 通知管理：管理员通知列表、已读标记、删除、批量操作 |

### 3.2 组件模块 (`src/components/`)

#### 3.2.1 布局组件 (`layout/`)

| 组件 | 职责 |
|------|------|
| `NavbarMenu.vue` | 顶部导航栏，包含搜索框、主题切换（亮色/暗色）、通知中心（SSE 实时推送）、智能对话入口 |
| `SidebarMenu.vue` | 侧边栏菜单，支持折叠展开，导航各功能模块（申请管理、贷款管理、用户管理、风控管理、系统管理） |

#### 3.2.2 通用组件 (`shared/`)

| 组件 | 职责 |
|------|------|
| `BaseTable.vue` | 通用表格组件，基于 Ant Design Vue `a-table` 封装，支持排序、筛选、分页、行选择、批量操作、自定义列插槽 |
| `BasePagination.vue` | 通用分页组件，支持页码导航、总数显示 |
| `DateRangePicker.vue` | 日期范围选择器，支持 v-model 绑定日期数组 |
| `ImagePreview.vue` | 图片预览组件，支持缩放、旋转、滚轮操作、下载 |

#### 3.2.3 业务组件

| 目录 | 职责 |
|------|------|
| `application-review/` | 申请审核组件：待办/已办贷款申请列表、待办/已办延期申请列表、申请详情弹窗（含认证材料查看、审核操作） |
| `product/` | 产品表格（含时间范围搜索、批量删除、上下架）、产品详情/编辑面板 |
| `user/` | 用户表格（信誉分排序）、黑名单表格、用户详情面板 |
| `risk/charts/` | 8 个 ECharts 图表组件（注册趋势、审批趋势、活跃度、贷款状态分布、资金用途、资金流动、用户状态、还款偏好） |
| `chat/` | AI 智能对话组件，基于 SSE 流式响应 |

### 3.3 组合式函数 (`src/composables/`)

| 文件 | 职责 |
|------|------|
| `useChatSSE.js` | 封装 AI 对话的 SSE 流式通信，管理消息列表、思考状态、流式内容渲染 |
| `useNotificationStream.js` | 封装通知的 SSE 实时推送，支持自动重连、桌面通知、连接状态管理 |

### 3.4 自定义 Hooks (`src/hooks/`)

3D 数据大屏相关，基于 Three.js 实现中国地图的 3D 渲染：

| 文件 | 职责 |
|------|------|
| `useFileLoader.js` | GeoJSON 文件加载 |
| `useCoord.js` | 经纬度坐标处理 |
| `useConversionStandardData.js` | 标准数据格式转换 |
| `useCountryMesh.js` | 国家网格模型生成 |
| `useMap3DCamera.js` | 3D 地图相机控制 |
| `useMapInteraction.js` | 地图交互（点击、悬浮） |
| `map/useMapMarkedLightPillar.js` | 地图标记光柱动画 |
| `useCSS2DRender.js` | CSS 2D 标签渲染 |
| `useCharts.js` | ECharts 实例封装 |
| `useCountry.js` | 国家/地区数据 |
| `useSequenceFrameAnimate.js` | 序列帧动画控制 |

### 3.5 状态管理模块 (`src/stores/`)

采用 Pinia 进行状态管理，使用 `pinia-plugin-persistedstate` 实现持久化。

| Store | 职责 | 主要状态 |
|-------|------|----------|
| `app.js` | 应用全局状态 | loading（请求队列）、sidebarCollapsed、theme（亮色/暗色，持久化） |
| `auth.js` | 用户认证状态 | token、refreshToken、userInfo、isAuthenticated（持久化） |
| `user.js` | 用户管理状态 | users（含分页）、blacklist（含分页）、userDetail、blacklistUserDetail |
| `loan.js` | 贷款产品状态 | products（含 loading/error）、currentProduct |
| `application.js` | 申请审核状态 | pendingApplications、completedApplications、pendingPostponeRequests、completedPostponeRequests、currentApplication |

## 五、状态管理流程图

### 5.1 认证流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  LoginView  │────>│  authAPI    │────>│  Backend    │
└─────────────┘     └─────────────┘     └─────────────┘
       │                   │
       │                   ▼
       │           ┌─────────────┐
       └──────────>│  authStore  │
                   │  - token    │
                   │  - refreshToken
                   │  - userInfo │
                   └─────────────┘
                         │
                         ▼
                   ┌─────────────┐
                   │ localStorage│
                   │ (持久化存储) │
                   └─────────────┘

Token 过期自动刷新：
请求 → 401 → 调用 refreshToken API → 更新 token → 重试请求
                                 └→ 刷新失败 → 强制登出
```

### 5.2 全局 Loading 控制

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   API请求   │────>│  request.js │────>│   appStore  │
└─────────────┘     └─────────────┘     └─────────────┘
                          │                    │
                          │                    ▼
                          ▼              showLoading()
                    请求拦截器            loadingCount++
                          │                    │
                          ▼                    ▼
                    发送请求              loading = true
                          │
                          ▼
                    响应拦截器
                          │
                          ▼
                    hideLoading()
                          │
                          ▼
                   loadingCount--
                   if (count === 0)
                     loading = false
```

### 5.3 数据流

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   View      │────>│   Store     │────>│    API      │
│  (用户操作)  │     │  (状态管理)  │     │  (接口请求)  │
└─────────────┘     └─────────────┘     └─────────────┘
       ▲                   │                   │
       │                   ▼                   ▼
       │             ┌─────────────┐     ┌─────────────┐
       └─────────────│   State     │<────│  Response   │
                     │  (响应式数据) │     │  (响应数据)  │
                     └─────────────┘     └─────────────┘
```

### 5.4 SSE 实时通知流

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  NavbarMenu │────>│useNotify-   │────>│  Backend    │
│  (通知面板)  │     │Stream       │     │  SSE 端点   │
└─────────────┘     └─────────────┘     └─────────────┘
       ▲                   │
       │                   ▼
       │             ┌─────────────┐
       └─────────────│  通知列表    │
                     │ 桌面通知     │
                     │ 未读计数     │
                     └─────────────┘

功能：
- 自动连接 SSE 流
- 收到新通知 → 更新通知列表 + 未读计数
- 支持桌面通知（需授权）
- 断线自动重连（最多10次）
- 全部已读 / 清空全部 / 单条操作
```

### 5.5 AI 对话流

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ ChatDialog  │────>│ useChatSSE  │────>│  Backend    │
│ (对话界面)   │     │ (SSE 流)    │     │  /chat/stream│
└─────────────┘     └─────────────┘     └─────────────┘
       ▲                   │
       │                   ▼
       │             ┌─────────────┐
```

## 七、命名规范

### 7.1 文件命名

- **Vue 组件**：PascalCase，如 `UserTable.vue`
- **JS 文件**：camelCase，如 `userStore.js`
- **CSS 文件**：kebab-case，如 `base-table.css`
- **组合式函数**：camelCase，以 `use` 开头，如 `useChatSSE.js`

### 7.2 组件命名

- **组件定义**：PascalCase
- **模板中使用**：PascalCase

### 7.3 Store 命名规范

- **Store 文件**：与业务模块同名，如 `user.js`
- **Store ID**：与文件名一致，如 `defineStore('user', ...)`
- **Action 命名**：
  - 异步获取数据：`fetch + 实体名`，如 `fetchUsers`
  - 设置数据：`set + 属性名`，如 `setAuthInfo`
  - 清除数据：`clear + 属性名`，如 `clearUserDetail`
  - 重置状态：`resetState`

### 7.4 API 命名规范

- **获取列表**：`get + 实体复数`，如 `getProducts`
- **获取详情**：`get + 实体 + Detail`，如 `getUserDetail`
- **创建**：`add + 实体`，如 `addProduct`
- **更新**：`update + 实体`，如 `updateProduct`
- **删除**：`delete + 实体`，如 `deleteProduct`
- **批量操作**：`batch + 操作 + 实体`，如 `batchDeleteProducts`

### 7.5 路由命名规范

- **路由 path**：kebab-case，如 `/pending-applications`
- **路由 name**：PascalCase，如 `PendingApplications`
- **懒加载**：使用动态 `import()` 实现路由懒加载
