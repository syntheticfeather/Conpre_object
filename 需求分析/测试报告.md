# 贷款服务平台系统软件测试报告

## 一、引言

### 1.1 编写目的

本文档旨在对贷款服务平台的全量核心功能接口进行全面测试验证，评估系统在功能正确性、数据一致性、安全性及异常处理等方面的表现，为系统上线提供质量保障依据。

### 1.2 项目背景

本项目为面向个人用户的在线贷款服务平台，支持用户注册登录、浏览贷款产品、提交贷款申请、上传认证材料，并由后台进行 AI 初审与人工复审。管理员可管理产品、审核申请、维护用户黑名单等。

### 1.3 系统简介

系统包含以下主要模块：

**认证模块**（Auth）：用户注册、登录、认证材料上传
**贷款产品模块**（LoanProduct）：产品查询、创建、上下架、选项管理
**贷款申请模块**（Application）：用户提交/撤回申请，管理员查看申请详情
**人工审核模块**（ManualApprove）：待办/已办列表、审核结果提交
**贷款订单模块**（LoanOrder）：用户查看订单状态
**用户管理模块**（User）：信息修改、黑名单管理、用户统计

### 1.4 术语和缩写词

|术语|说明|
|--|--|
|JWT：JSON Web Token|用于身份认证|
|PENDING / APPROVED / REJECTED|贷款申请状态|
|form-data|HTTP请求中用于上传文件的多部分表单格式|
|CI/CD|持续集成/持续部署|

## 二、测试概要

### 2.1 测试用例设计

采用 场景驱动 + 边界值 + 异常流 策略，覆盖以下维度：

|模块|核心测试点|
|--|--|
|Auth|注册唯一性、密码强度、Token 鉴权、材料必填校验|
|Loan Product|产品创建参数合法性、选项批量操作、上下架状态同步|
|Application|期数是否在 terms 范围内、撤回后状态变更|
|Manual Approve|审核权限控制、拒绝原因拼接、状态流转（AI_REJECTED → 人工拒绝）|
|Loan Order|订单状态（正常/逾期）、与申请状态一致性|
|User|黑名单增删查、信用分筛选表达式解析、头像上传格式限制|

### 2.2 测试环境与配置

**服务地址**：http://localhost:8080
**测试工具**：Postman
**数据库**：MySQL
**依赖中间件**：Redis（Token 存储）

### 2.3 测试方法与工具

**手动功能测试**：通过 Postman 执行正向/反向用例
**数据验证**：比对接口返回与数据库记录
**安全测试**：验证未授权访问（如无 Token 访问 /api/users/me 应返回 401）
**边界测试**：如贷款金额最大值（12位含2小数）、利率精度（4位小数）

## 四、测试结论与建议

**测试结论**
系统整体功能完整、流程闭环、状态流转正确。各模块接口符合设计文档要求，在典型业务场景（如用户申请 → 人工审核 → 生成订单）下表现稳定。安全性方面，Token 鉴权机制有效，关键操作均有权限控制。

**建议**

- 统一 API 响应规范
- 字段命名统一（如 userName vs name）
- 移除 JSON 中多余空格（如 "code ": 200 → "code": 200）
- 增强输入校验
- 贷款产品创建时校验 termStep > 0
- 用户密码增加复杂度策略（至少8位，含大小写+数字）
- 明确 reviewTime 在所有审核结果下的赋值逻辑
- 撤回申请后状态应为 CANCELLED 并立即生效
- 推进自动化测试
