## 1. 引言

### 1.1 编写目的
本报告旨在详细描述"多数据风控系统（贷款业务）"的软件体系结构设计，明确系统的类结构、关键类之间的交互关系、数据模型及服务实现方式。本设计为开发团队提供实现依据，确保系统开发、测试和维护的一致性。

### 1.2 读者对象
本报告面向系统开发人员、测试人员及项目管理人员。

### 1.3 软件系统概述
本系统是一个面向互联网金融场景的个人贷款风控系统，支持用户在线申请小额贷款。系统通过整合多源数据（如征信、运营商、社保、行为日志等），利用规则引擎与机器学习模型进行风险评估，实现自动化审批与额度定价。目标用户包括金融机构风控部门与终端借款人。

## 2. 软件设计约束和原则

### 2.1 软件设计约束
1. **运行环境**：系统部署在Linux服务器，支持高并发访问
2. **技术栈**：Spring Boot 3.0+，Java 17，MySQL 8.0，Redis
3. **接口规范**：RESTful API，JSON数据格式
4. **性能要求**：贷款申请审批响应时间≤2秒，支持每秒1000+并发请求
5. **安全要求**：符合金融行业安全规范，支持OAuth2.0认证

### 2.2 软件设计原则
1. **分层架构**：表现层、服务层、数据层三层分离
2. **高内聚低耦合**：每个服务模块职责单一，接口清晰
3. **可扩展性**：支持未来接入第三方风控模型
4. **可维护性**：模块化设计，代码结构清晰
5. **容错性**：关键业务流程有完善的异常处理机制

## 3. 详细设计方案

### 3.1 系统体系结构设计

系统采用分层架构设计，核心服务层包含多个独立服务模块，通过HTTP/JSON协议通信。整体架构如下：

```
表现层（Controller）
│
├── 用户服务层（UserService）
├── 贷款项目服务层（LoanProductService）
├── 申请服务层（ApplicationService）
├── 贷后服务层（OrderService）
├── 支付服务层（PayService）
├── 认证服务层（AuthService）
├── 安全服务层（Security）
└── 风险评估服务层（RiskAssessService）
    ├── AI自动审核服务（AIApproveService）
    └── 人工审核服务（ManualApproveService）
```

**关键设计说明**：
- 系统采用"决策中心"模式，由ApplicationService作为协调者，聚合多个风控子服务结果
- AuthService作为核心认证服务，提供资产认证、银行账户认证、征信认证等能力
- RiskAssessService作为风险评估核心，整合AIApproveService和ManualApproveService

### 3.3 关键交互流程

#### 3.3.1 贷款申请流程

1. 用户提交贷款申请，包括个人信息、资产信息等
2. ApplicationService调用AuthService进行多源认证
3. AuthService整合资产认证、银行账户认证、征信认证等数据
4. RiskAssessService调用AIApproveService进行AI自动审核
5. 若AI审核通过，直接完成贷款审批；若不通过，调用ManualApproveSendService发送人工审核任务
6. 人工审核员通过ManualApproveService进行审核
7. 审核结果返回ApplicationService，生成贷款订单

#### 3.3.2 贷后管理流程

1. 用户发起还款请求
2. OrderService调用PayService处理支付
3. 还款成功后，更新Loan状态和还款记录
4. 若用户申请延期，调用OrderService的postpone方法
5. 延期申请进入ManualApproveSendService流程，等待人工审核

### 3.5 部署设计

系统采用微服务架构部署，各服务独立部署，通过Spring Cloud实现服务发现与负载均衡：

```
- 前端服务：html, css, js与后端一起静态资源部署
- 后端服务：
  ├── UserService (用户服务)
  ├── LoanProductService (贷款产品服务)
  ├── ApplicationService (申请服务)
  ├── OrderService (贷后服务)
  ├── PayService (支付服务)
  ├── AuthService (认证服务)
  ├── RiskAssessService (风险评估服务)
- 数据库：MySQL集群（主从复制）
- 缓存：Redis集群（用于会话管理和缓存热点数据）
- 消息队列：RabbitMQ（用于异步任务处理）
```

**部署架构图**：
```
                       [客户端] 
                          |
                          v
[UserService] [LoanProductService] [ApplicationService] [OrderService] [PayService] [AuthService] [RiskAssessService]
                          |
                          v
[MySQL集群] [Redis集群] [RabbitMQ]
```

## 4. 设计模式与复用机制

### 4.1 采用的设计模式

1. **策略模式**：用于贷款审批策略，支持多种审批策略的动态切换
    - LoanApproveStrategy接口
    - AIAproveStrategy实现类
    - ManualApproveStrategy实现类

2. **工厂模式**：用于创建不同类型的认证服务
    - AuthFactory类
    - AssetAuthStrategy实现类
    - BankAccountAuthStrategy实现类

3. **观察者模式**：用于贷款状态变更通知
    - LoanStatusObserver接口
    - SmsService实现类（短信通知）
    - EmailService实现类（邮件通知）

### 4.2 复用机制

1. **服务复用**：AuthService被多个服务（ApplicationService、RiskAssessService等）复用
2. **工具类复用**：Utils包中的工具类（如JwtUtils、RedisUtils）,简化代码编写，被各服务模块复用
3. **异常处理复用**：Exception包中的自定义异常类被各服务模块复用

## 5. 系统质量属性设计

### 5.1 性能设计

1. **缓存机制**：对热门贷款产品信息、用户基本信息进行缓存，减少数据库访问
2. **异步处理**：使用RabbitMQ处理短信通知、日志记录等非核心业务
3. **数据库优化**：对贷款订单表进行分库分表，支持高并发查询

### 5.2 安全设计

1. **认证安全**：使用JWT进行用户认证，确保请求安全
2. **数据安全**：敏感数据（如身份证号、银行卡号）加密存储
3. **权限控制**：基于角色的访问控制（RBAC），确保不同角色访问权限

### 5.3 可维护性设计

1. **模块化设计**：每个服务职责单一，便于独立开发和测试
2. **代码规范**：统一的代码规范和注释要求
3. **日志记录**：关键业务流程记录详细日志，便于问题排查
